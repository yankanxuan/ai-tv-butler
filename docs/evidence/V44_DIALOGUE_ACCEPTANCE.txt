口径说明
------------------------------------------------------------------------------
* 每条话术都在完整链路里跑：用户说话 → 路由 → 工具调用 → 回复 → 确认 → 执行。
* 「是否误执行电视动作」的唯一判据是 agent.run 的调用次数（这是唯一能碰电视的出口）。
* 事实断言全部对照真实工具返回值（LibraryTools.summary/overview/search/recent/item），
  不对照回复措辞。
* 每条话术跑 3 次（reps=3）；PASS 表示 3 次全部通过；模型有随机性，FAIL 会标出失败轮次。
* 表中 agent.run 列：H（确认播放）与 O（重复确认）为 1 是**预期**——用户明确确认后才执行一次；
  I（电视现在在放什么）为 1 是**只读查询**（命令是「现在播放的是什么」），断言要求该轮所有
  命令都是只读提问，不得出现播放/暂停等状态变更。其余话术必须为 0。

未验收（真实设备 / 真人手机，一律 verified=false，不伪造）
------------------------------------------------------------------------------
  · 真实电视（小米 TV / 原生助手）上的实际播放与原生助手抑制
    原因：验收机没有可用的电视/ADB 目标，所有电视动作都只到 agent.run 边界；真机行为需要在现场用遥控器复验。
  · 真人手机（语音入口 / 小爱同学）端到端时延与打断
    原因：无法自动化真人说话与手机麦克风链路；本跑批使用 source="text" 模拟同一句话。
  · TTS 播报音质与打断（VoiceResponder）
    原因：跑批使用无副作用的 responder 桩件（tts_ms=0），不触发真实 TTS。
  · I 项的设备观测
    原因：没有真实电视可观测，使用注入的固定设备观测（PLAYING / 已知片名与集数）替代，仅验证"回复与观测一致"这一逻辑。
