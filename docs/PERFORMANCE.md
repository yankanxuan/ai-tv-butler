# 常用指令加速

## 当前执行方式

常用指令先在本机解析，不调用模型：

```bash
ai-tv cmd "暂停"
ai-tv cmd "继续播放"
ai-tv cmd "打开飞牛"
ai-tv cmd "打开飞牛继续播放"
ai-tv cmd "打开飞牛播放一部短剧"
ai-tv cmd "打开飞牛播放穿成野神我靠香火斩诸神第一部第一集" --json
```

- 暂停、继续、返回、音量加减：直接发送一个按键，返回“已发送按键”，不额外扫描界面。
- 打开飞牛：已在前台就复用当前页面；从其他应用进入时才启动。
- 继续播放：已在播放器则直接发送 PLAY，并做轻量验证。
- 飞牛短剧播放：识别首页、媒体库列表、剧目详情、季详情、单集文件详情、播放器，选择必要步骤。每一步就绪后继续，不再强制等待 5+4+4 秒。
- 指定片名：传递片名、季、集，找不到时明确失败，不改播首个结果。剧名需能精确匹配，简称可通过 title_aliases 配置。
- 复杂指令、跨应用请求、推荐等仍交给模型，不把多步骤请求错误简化为一个按键。

现有 `tv_run_flow` 对 feiniu_tv / feiniu_drama 默认复用这套导航，所以 CLI 和 MCP 共用加速逻辑。其他自定义 flow 保留；末尾 wait_play 已确认的播放结果直接复用，不重复检查。

## 减少界面读取

UI 每次只解析一份新快照，保留父子关系、匿名焦点、focusable 属性。定位卡片时沿标题向上找到可操作父节点；焦点卡片缩放或列表滚动后，重新按标题绑定，避免复用旧坐标。

播放状态一次读取窗口，最多一次查询进程；已确认媒体或音频状态时跳过 uiautomator。飞牛导航的播放验证显式关闭 UI dump，并绑定 com.trim.tv。通用搜索流程用控件就绪轮询替换固定等待。

2026-11-10，小米 MiTV-ASTP0 / Android 9 / 192.0.2.20:5555。以下为单次抽样，不是稳定延迟保证；计时覆盖 Agent.run，不包括网页对话工具调度与文字回复。

| 指令与起始条件 | 用时 | 模型调用 |

| 飞牛继续播放，已在播放器 | 1.97 秒 | 0 |
| 飞牛首页 → 短剧库 → 首部短剧 → 播放 | 11.83 秒 | 0 |

## 配置

```yaml
agent:
  fast_path: true          # 常用明确指令直接执行
  smart_navigation: true  # MCP/工具中的飞牛 flow 使用页面导航
ui:
  fast_poll_interval: 0.2
  navigation_timeout: 60  # 整次页面导航的时间预算
  wait_timeout: 20        # 单阶段等待上限
  max_search_pages: 12
apps:
  feiniu_tv:
    package: com.trim.tv
    title_aliases:
      野神: 穿成野神我靠香火斩诸神
```

要使用模型执行常用命令，设 fast_path:false（配合 use_llm:true）。要让 tv_run_flow 使用旧的自定义按键步骤，再设 smart_navigation:false。`--offline` 不调用模型，仍使用页面导航。

结果中的 `elapsed` 为总耗时，`timings` 包含 state / ui / launch / verify 等阶段（按实际执行出现）；普通 CLI 也显示阶段耗时。`llm_calls:0` 表示直接执行的常用指令未发模型请求。

## 回归验证

`make test` 同时运行旧的 22 项集成检查与快速路径 unittest。新测试使用内存设备验证：明确指令不调用模型、已在播放器不重新启动/读 UI、打开不自动播放、指定片名不丢失、父卡片焦点定位、屏幕下方选集需先滚动、文件详情需再播放，以及旧 flow 不重复验证。

当前已实现对可见剧目和选集标签的定位与有限向下翻页；没有完整媒体库索引。较深列表、尚不可见的特定集数、不同飞牛版本的页面布局仍可能超时，失败会返回步骤与耗时，不能视为已支持任意片名任意集的瞬时直达。
